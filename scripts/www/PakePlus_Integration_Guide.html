PakePlus 集成指南

修复 保存视频到相册闪退 + 配音只有一个有声音 两大问题

目标设备：Redmi K80 Ultra (澎湃OS 3.0, Android 14/15)

⚠️ 核心问题诊断

之前的修复无效，原因是：Java 文件包名错误。PakePlus 的包名是 com.app.pakeplus，不是 com.zsag.ai。错误的包名导致 Kotlin 代码无法编译，window.AndroidMediaStore 桥梁从未注册成功。

因此 JS 代码中的 if(typeof window.AndroidMediaStore!=='undefined') 检测始终为 false，保存流程走了 <a download> 降级路径——这对大视频会导致 WebView 内存溢出闪退。

步骤 C：在 onCreate 中初始化

在 onCreate() 方法中，WebView 创建之后添加：

    super.onCreate(savedInstanceState)
    // ... 已有的代码 ...

    // ... WebView 初始化代码 ...
}

步骤 D：配置 WebView（关键修改）

找到 WebView 的 Settings 配置代码（通常在 initWebView() 或 setupWebView() 方法中），添加两行关键代码：

private fun initWebView(webView: WebView) {
    val settings = webView.settings

    // ===== 关键修复 1: 允许无用户手势播放媒体 =====
    // 解决"配音只有一个有声音"的问题
    // WebView 默认 mediaPlaybackRequiresUserGesture=true，
    // 导致第一次点击后后续 audio.play() 被阻止
    settings.mediaPlaybackRequiresUserGesture = false  // ← 添加这行

    // ... 已有的 settings 配置 ...
    settings.javaScriptEnabled = true
    settings.domStorageEnabled = true
    // ...

    // ===== 关键修复 2: 注册 MediaStore JavascriptInterface =====
    // JavaScript 通过 window.AndroidMediaStore.saveVideo() 调用原生 MediaStore API
    // 这是 Android 13+ 保存到相册的唯一稳定方案
    webView.addJavascriptInterface(mediaStoreSaver, "AndroidMediaStore")  // ← 添加这行

    // ... 已有的 WebViewClient / WebChromeClient 配置 ...
}
✅ 验证方法

修改完成后，在 JS 控制台输入 typeof window.AndroidMediaStore，应返回 "object" 而非 "undefined"。

输入 typeof window.AndroidMediaStore.saveVideo，应返回 "function"。

保存流程说明

小文件（< 20MB）— 直接 base64 传输

JS: FileReader.readAsDataURL(blob) → base64 字符串
  → window.AndroidMediaStore.saveVideo(base64, fileName)
Kotlin: Base64.decode → ContentResolver.insert(MediaStore.Video) → OutputStream.write

大文件（≥ 20MB）— 分块传输（防 OOM）

JS: blob.slice(0, 2MB) → base64 → appendChunk(sessionId, chunk1)
    blob.slice(2MB, 4MB) → base64 → appendChunk(sessionId, chunk2)
    ...
    finalizeChunkedSave(sessionId)
Kotlin: 每个 chunk 追加写入 cacheDir 临时文件
        → finalizeChunkedSave: 临时文件 → ContentResolver → MediaStore → 删除临时文件

超大文件（> 200MB）— 降级下载

JS: <a download> → 保存到 Downloads 文件夹（非相册）

音频问题修复说明

根本原因

Android WebView 默认 mediaPlaybackRequiresUserGesture = true。这意味着：

  • 第一次点击试听配音 → 有声音（因为点击就是 user gesture）
  • 后续点击试听其他配音 → 无声音（如果 play() 不在用户手势的同步调用栈中）

特别是在 _previewVoiceSS 中，预生成音频的 play() 调用可能在异步回调中执行（如 FileReader.onload 后），此时已脱离用户手势上下文。

修复方案

在 MainActivity.kt 中设置 settings.mediaPlaybackRequiresUserGesture = false（见上方步骤 D）。

JS 侧已使用 _createHiddenAudio() 创建 DOM 挂载的 audio 元素，配合此设置即可正常播放多个音频。

PakePlus app.json 说明

PakePlus 的 app.json 不支持 "permissions" 字段（这不是 PakePlus 的标准格式）。权限由 AndroidManifest.xml 控制。app.json 中的字段是功能开关：

字段 值 说明
downloadtrue启用下载功能
gallerytrue启用相册访问
cameratrue启用摄像头（getUserMedia）
microphonetrue启用麦克风（录音）
⚠️ 注意事项
  • PakePlus 通过 GitHub Actions 云端编译，修改代码后需要 push 到你的 fork 仓库触发编译
  • MediaStoreSaver.kt 必须放在 app/src/main/java/com/app/pakeplus/ 目录下（包名必须匹配）
  • 如果 PakePlus 的包名不同（检查 app/build.gradle.kts 中的 applicationId），需要相应修改 MediaStoreSaver.kt 的 package 声明
  • 修改 MainActivity.kt 时，不要删除已有代码，只添加新代码
